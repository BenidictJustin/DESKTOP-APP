# DommUnity System Alpha Testing Report

---

## 1. Overview

This document presents the **Alpha Testing Report** for the **DommUnity System**. While the stress testing was performed by the proponents to test system limits under heavy workloads, the alpha testing was conducted directly by the actual intended users of the system: the **CES Head / Admin** and the **CES Coordinator**. 

The main goal of alpha testing was to observe how real users interact with the system, evaluate usability across all core workflows, gather direct user feedback on features and interface design, identify confusing steps or minor bugs, and make the necessary improvements before final deployment.

---

## 2. CES Head / Admin User Experience and Feedback

The CES Head / Admin tested the administrative features of DommUnity. The test began with logging into the system using admin credentials and accessing the Admin Dashboard. The user found the dashboard layout easy to understand, noting that the summary counter cards for stock totals, scheduled outreaches, and pending reports gave a clear overview of daily operations right after login. Navigation through the sidebar menu was smooth, allowing quick access to all administrative modules.

In the Inventory Management module, the admin tested adding new stock items, browsing the item catalog, and recording item release transactions. The admin noted that the forms for adding catalog items and releasing supplies were straightforward to fill out. However, during the initial release process, the admin found it slightly confusing when searching for specific items if the exact item name was not remembered. To address this feedback, the proponents improved the inventory search and category dropdown filters so that items can be searched easily by partial names or categories. In the Outreach Events module, the admin scheduled new community outreach events, used the date picker to set schedules, and viewed both upcoming and completed activities. The event calendar and status badges made tracking events simple and visual.

The admin also tested the Department and Organization Directory, Donor Management, and User Accounts modules. Adding department profiles and registering donation batches worked smoothly with clear input validation messages. When managing user accounts, the admin created new coordinator accounts, edited account details, and tested locking and unlocking account access. The admin suggested making the confirmation messages clearer before saving changes or updating user statuses. The proponents updated the confirmation popups and notifications across all administrative forms so that actions are clearly explained before they are finalized.

The most critical workflow tested by the admin was the Reports Review module. The admin opened submitted narrative reports, inspected document details in the preview modal, and tested approving reports as well as returning reports with written feedback. The admin appreciated being able to read full report narratives directly inside the system and export finalized reports to PDF. An early issue was observed where long written remarks for returned reports did not scroll properly inside the feedback box. The proponents adjusted the layout of the review modal to ensure all feedback text is easy to read and edit. Following these refinements, the CES Head / Admin found the administrative workflows easy to navigate, functional, and well-suited for daily office management.

---

## 3. CES Coordinator User Experience and Feedback

The CES Coordinator tested the coordinator workspace and report generation workflows. The testing started by logging in as a coordinator and viewing the Coordinator Dashboard, which displayed personal report submission statistics and upcoming department outreaches. The coordinator then created a new outreach narrative report using the built-in Document Editor.

The coordinator found the built-in document template and text formatting tools easy to use, as they closely resemble familiar word-processing software. The coordinator typed narrative sections, formatted headings, inserted data tables, and embedded outreach photo documentation directly into the canvas. During initial testing, the coordinator noticed that uploading very large photo files caused a brief pause when saving drafts. The coordinator also suggested adding a clearer auto-save indicator so users know when their draft is safely saved. The proponents addressed this by automatically shrinking uploaded pictures and adding a visible saving status indicator in the editor. These changes made the writing and draft-saving experience fast, smooth, and reassuring.

After completing a draft, the coordinator submitted the narrative report for administrative review and tracked its progress across the Compiled Reports page. The coordinator tested viewing reports organized under Draft, Submitted, Returned, and Approved status tabs. When a report was returned with admin remarks, the coordinator received the feedback notification, reopened the report in the editor, made the requested revisions, and resubmitted it without issue. The coordinator also tested opening approved reports in the Document Viewer and exporting them as standardized PDF documents. The exported PDF files maintained clean formatting, proper page breaks, and clear image placements.

Overall, the CES Coordinator shared positive feedback regarding the simplicity of the reporting workflow. The coordinator noted that the built-in template, real-time draft saving, and clear status tracking significantly reduced the time and effort needed to prepare and submit official outreach documentation.

---

## 4. Summary and Final Outcome

The Alpha Testing provided valuable firsthand insights from the actual intended users of DommUnity. Testing by the CES Head / Admin and the CES Coordinator confirmed that the system's core features are practical, user-friendly, and aligned with the actual workflows of community extension services.

All minor issues, confusing interface steps, and feedback gathered during alpha testing—including improved search filters, clearer confirmation popups, responsive document auto-saving, and refined PDF formatting—were successfully addressed by the proponents. After these improvements were applied, both the CES Head / Admin and the CES Coordinator verified that the DommUnity application is responsive, reliable, and ready for regular institutional use.
